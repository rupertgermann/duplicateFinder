# Domain docs

This repo uses a single context. Before exploring domain code, read `GLOSSARY.md` at the repo root and the relevant decisions in `docs/adr/` if they exist. Continue with the available context when either is absent.

Use the glossary’s terms in ticket titles, proposals, and test names. Surface any conflict with an existing ADR and explain why the decision should be revisited.

Create `GLOSSARY.md` when domain modeling resolves the first term. Create `docs/adr/` when there is a decision to record.
